# Harness для этого репозитория

## Назначение

Harness хранит принятый контекст, критерии результата и доказательства проверок.
Используются идеи коротких AGENTS/планов/приёмки из community-проектов и OpenAI
Cookbook. Сторонние CLI/глобальные skills не устанавливались; файлы написаны
специально для нашего MVP. Источники и решение о reuse — в [research.md](research.md).

## Что уже исполнимо

`python3 scripts/check_harness.py` / `make check-harness`:
- проверяет обязательные файлы и внутренние Markdown-ссылки;
- проверяет синтаксис и структуру synthetic fixture и eval cases;
- проверяет уникальность ID, координаты, существование source/expected IDs;
- проверяет отсутствие product scaffold на стадии harness-only;
- проверяет, что .env.example содержит пустой ключ и безопасные настройки.

Это не тест приложения и не оценка LLM. Статус реализации явно хранится
в `docs/progress.md`: `Stage: harness-only` сейчас, `Stage: implementation`
после утверждения и начала этапа 1.

## Как запускать работу после утверждения

Пример запроса агенту:

> Прочитай AGENTS.md и docs/progress.md. Выполни ближайший незавершённый этап
> docs/implementation-plan.md в рамках docs/product-spec.md. Соблюдай контракт.
> Проверь результат командами этапа, запиши evidence и остановись на блокере,
> который нельзя решить без новых данных/доступа. Не расширяй scope.

Рекомендуемый режим на этот срок: основной интегратор реализует зависимые
этапы последовательно; сбор данных идёт отдельно; независимый reviewer
проверяет законченный текстовый путь и финальные изменения. Это сокращает
конфликты. UI можно делегировать после фиксации контрактов и владения файлами.

Каждый task packet содержит: цель, читаемые документы, owned files, вход/выход,
критерий готовности, команды проверки, ограничения и требуемый отчёт.
Отчёт исполнителя: files changed, tests + exit codes, evidence, blockers.
Заявление исполнителя не заменяет проверку интегратором.

## Проверки после scaffold

| Команда | Что доказывает |
|---|---|
| `pnpm lint` | Правила исходников |
| `pnpm typecheck` | Совместимость типов |
| `pnpm test` | Фильтры, контракты, источники, ошибки, ссылки |
| `pnpm build` | Production-сборка |
| `pnpm test:e2e` | Основные пользовательские пути и адаптивность |
| `pnpm eval:retrieval` | Попадание размеченных мест в выдачу |
| `pnpm eval:live` | Схема/grounding/стоимость конкретной модели; платно |

Эти команды пока являются планом; package.json ещё нет. В этап 1 входит их
настройка. Runtime зависимости/ключи не нужны для текущего check-harness.

## Как читать eval cases

`evals/cases.json` — сценарии, а не отчёт о прошедших тестах. `defaults` задаёт
общий запрос; `input` глубоко перекрывает отдельные поля. `now` — тестовые часы.
`expected` содержит статусы, обязательные/запрещённые IDs и ручные утверждения.
`kind` определяет уровень: retrieval, generation, integration, ui, data.
`priority` определяет gate: P0 обязателен; P1 проверяется при включённой функции.
Unicode и поиск казахских названий — P0; казахская генерация и голос — P1.
`setup` позволяет менять окружение (отказ геолокации, API timeout) или fixture.
Ожидание `mustIncludeAny` требует хотя бы один ID, `mustExclude` запрещает все
перечисленные. Эти assertions реализуются на соответствующем этапе плана.

Сначала synthetic-тесты инвариантов, затем отдельные размеченные реальные POI.
Нельзя вычислять «качество реального поиска» по синтетике и выдавать это за
готовность городского советчика. Live-сравнение генераторов использует один
замороженный retrieval context для честного сравнения.

## Доступы, расходы и внешние проекты

Сейчас не требуется предоставлять ключи для чтения плана. Перед первым live-вызовом
настроить OpenRouter server env безопасным способом; не просить ключ в сообщении.
Не создавать OpenAI project/key, поскольку пользователь выбрал OpenRouter.
Программный прогноз расходов проверяется перед батчем, фактический usage — после.
Автоповторы ограничены; expensive/новая модель не выбирается молча.

Чужие проекты исследуются в /tmp, с pinned commit и проверкой package scripts.
Рабочая сборка не означает корректного поиска; отсутствие лицензии отмечается
до переноса. MIT/Apache компоненты добавляются точечно с соблюдением notices.
