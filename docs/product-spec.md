# Спецификация MVP: Куда в Астане

Статус: конкретный дизайн для утверждения. Стек одобрен пользователем;
этот документ и план подготовлены по его запросу. Реализация ещё не начата.

## Задача и успех

Человек выбирает локацию в Астане, описывает желание или категорию и получает
до трёх реальных мест с объяснением, примерным временем посещения, конкретным
занятием и переходом к маршруту. Демо показывает RAG на автоматически собранных
POI и честно обозначенную демонстрационную персонализацию.

Дедлайн: 20.10.2026 23:59 Asia/Almaty. Цель сдачи: 20:00. Заморозка новых
функций: 17:30. Предположение для расписания: основной разработчик/интегратор
и отдельный уже работающий сборщик данных; размер человеческой команды не известен.

## P0: обязательная версия

1. Mobile-first сайт; проверка на ширинах 390 и 1440 px, без горизонтального скролла.
2. Локация по разрешению либо выбор из трёх ориентиров: EXPO, Бәйтерек, набережная.
   Реальная геолокация — только по нажатию. При отказе доступен ручной выбор.
3. Категории и текст работают совместно. Видимые фильтры: радиус 1/2/5 км,
   время на посещение 30/60/120 минут (дорога отдельно), состав компании. Бюджет на человека учитывается
   только по известным ценам; неизвестные цены не считаются подходящими.
4. До трёх результатов. Карточка: название, категория, рейтинг/число оценок
   при наличии, расстояние по прямой, краткое описание, почему подходит,
   что сделать, оценка времени посещения, кнопки подробностей и маршрута.
5. Подробности: адрес, часы/неизвестность, источники и даты, социальные ссылки
   при наличии. Два реальных отзыва показываются по раскрытию, если собраны.
6. Маршрут открывается через HTTPS в 2ГИС или Google Maps. Координаты и порядок
   lon/lat проверяются; возможность web fallback тестируется на телефоне.
7. Три демо-профиля: студент, турист, семья. Смена профиля меняет ранжирование,
   но не отменяет явные ограничения. На экране есть «Демо-профиль» и «Что учтено».
8. Сохранения/«не интересно» хранятся локально; есть сброс демо-истории.
9. Геофильтры + смысловой поиск + ограниченная генерация на найденных POI.
10. Понятные состояния: загрузка, нет результатов, неполные данные, API недоступен.
    При сбое генерации допустим детерминированный список из каталога с пометкой
    «Показаны результаты поиска; объяснение AI временно недоступно».
    Если сломался разбор непустого запроса, возвращается уточнение без рекомендаций;
    нельзя молча потерять ограничения из текста.

## P1: после устойчивого полного пути

- Голос: запись до 20 секунд/5 MB, распознавание, редактирование текста и обычный поиск.
  Поддерживаемые MIME выбираются через MediaRecorder.isTypeSupported; проверить
  Safari/iPhone и Chrome/Android. При несовместимости доступен текст.
- Ответ на языке запроса: русский — основной, казахский — проверяемый дополнительный.
- Небольшая визуальная полировка и установка иконки/manifest при запасе времени.

Встроенная карта, оптимизация маршрутов, авторизация, backend-профиль,
бронирование, групповые комнаты и live-скрейпинг в запросе выходят за P0.

## UX и данные

На телефоне: поле запроса и категории сверху, карточки ниже, подробности в Sheet.
На ноутбуке: фильтры слева, результаты и подробности рядом. Клавиатурный фокус,
подписи кнопок, контраст и доступность диалогов входят в готовность.

«Что учтено» перечисляет выбранную локацию, фильтры, запрос и активный демо-профиль.
Не показывать точные координаты без необходимости. История не хранит координаты.
Голос отправляется провайдеру только после явного запуска записи; объяснить это
в UI. Аудио приложение не сохраняет после обработки.

Подтверждённые данные и генерируемые идеи имеют разные подписи. Расписание даёт
«по расписанию открыто», а не гарантию фактической доступности. При неизвестных
часах показывать «Время работы не подтверждено». Оценки пути и посещения не
объявлять точными. Источники отзывов и социальных утверждений сохраняются.

## Архитектура

Один Next.js проект с серверными Route Handlers. TypeScript strict. Tailwind и
выборочные компоненты shadcn/ui. Zod валидирует импорт, запросы и ответы LLM.
Провайдер — OpenRouter через серверный адаптер; ключ не доступен браузеру.
Модель задаётся env; исходный кандидат выбирается по исследованию и затем
сравнивается на сценариях. Новые model IDs требуют повторной проверки возможностей.

Данные поставляются сборщиком как JSON/JSONL, нормализуются в versioned JSON.
Эмбеддинги считаются заранее и сохраняются с model ID, размерностью, хешем данных
и версией описания. Запрос и каталог используют одну модель и размерность.
В serverless runtime каталог читается; обновление — новая сборка/развёртывание.

Путь запроса:
1. Валидация → извлечение структурированного намерения.
2. Явные UI-фильтры и текстовые ограничения согласуются; конфликт требует уточнения.
3. Геофильтр и проверяемые жёсткие ограничения.
4. Гибридное ранжирование: смысл, теги/слова, расстояние, затем профиль/разнообразие.
5. Не более 8 кандидатов в генерацию, не более 3 рекомендаций на выходе.
6. Проверка ID и evidence ID; фактические поля карточек подставляются сервером.

На старте веса ранжирования: смысл 0.55, слова/теги 0.20, близость 0.15,
профиль 0.10. Компоненты нормализованы 0–1; явные ограничения применяются раньше.
Это исходная гипотеза для retrieval eval, не утверждение о лучшей формуле.

## Приёмка и бюджет

Обязательные инварианты: 100% рекомендованных ID есть в отфильтрованном каталоге;
0 придуманных рейтингов, URL и часов; отсутствующие обязательные свойства
не объявляются подтверждёнными. До 3 результатов, явная маркировка synthetic/demo.

На 12 вручную размеченных реальных запросах: подходящее место в top-3 минимум
для 10 запросов; все явные ограничения соблюдены; каждое объяснение проверено
на соответствие источникам. Synthetic-набор отдельно проверяет крайние случаи.
Это критерии приёмки, текущих измеренных результатов нет.

Для сравнения моделей: фиксировать набор, prompt version, model/provider, стоимость,
TTFT/общую задержку, JSON validity, unsupported claims. 3 модели × 12 запросов;
оценочный лимит $0.50, проверять стоимость до запуска и после каждого батча.
Случайные повторения не считать независимыми примерами качества.

Общий доступный бюджет OpenRouter — $6 со слов пользователя. План: $0.50 сравнение,
$1.50 разработка, $1.00 индексация/аудио/повторы, $3.00 резерв. Для публичной ссылки
предусмотреть ограничение частоты запросов и лимит ключа у провайдера; in-memory
счётчик не считать глобальным лимитом в serverless.
